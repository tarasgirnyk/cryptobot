# Продуктова концепція CryptoBOT

Статус документа: первинні продуктові рішення. Частина технічних припущень
має бути підтверджена Андрієм.

## 1. Що продаємо

CryptoBOT — це SaaS-платформа для автоматизованої торгівлі через API біржі.
Платформа надає користувачу простий інтерфейс над торговим ботом, paper trading,
підключення власного біржового акаунта, запуск алгоритму, контроль ризику,
статистику та сповіщення.

Користувачу продається доступ до платформи за підпискою, а не бот як окремий
файл, не інвестиційний депозит і не передача коштів компанії в управління.

## 2. Погоджені рішення

- [x] Формат продукту — SaaS-платформа.
- [x] Кошти залишаються на особистому біржовому акаунті користувача.
- [x] Підключення реальної торгівлі відбувається через API-ключ користувача.
- [x] API-ключ не повинен мати права виведення коштів.
- [x] Для першої версії розглядається підтримка тільки Binance.
- [x] `Paper` — безкоштовна симуляція торгівлі на тестовому балансі.
- [x] На Paper не виконуються реальні угоди.
- [x] Після оплати підписки користувач може підключити API для реальної торгівлі.
- [x] Попередня ціна підписки — 100 USD на місяць.
- [x] Попередній технічний мінімум торгового депозиту — 10 USD.
- [x] Розмір депозиту не змінює базову ціну підписки.

## 3. Попередній клієнтський шлях

```text
Реклама або рекомендація
  → реєстрація у SaaS
  → безкоштовний Paper
  → симуляція на тестовому балансі
  → перегляд угод, P&L і просадки
  → оплата підписки 100 USD/місяць
  → підключення Binance API без права виведення
  → перевірка API та ризик-профілю
  → запуск реальної торгівлі
  → звітність, контроль і зупинка через платформу
```

## 4. Paper

Paper є безкоштовним входом у продукт і використовується для:

- демонстрації реальної логіки алгоритму на віртуальному балансі;
- навчання користувача;
- показу не тільки прибутку, а й збиткових періодів та просадки;
- перевірки зрозумілості інтерфейсу;
- формування власної історії користувача до підключення реальних коштів;
- конверсії користувача у платну підписку.

Paper не повинен створювати враження, що віртуальний результат гарантовано
повториться на реальному акаунті. В інтерфейсі потрібно пояснити відмінності у
виконанні, ліквідності, комісіях, funding і прослизанні.

## 5. Платна підписка

Попередня базова ціна: 100 USD на місяць.

Підписка відкриває:

- підключення Binance API;
- виконання реальних угод у межах дозволеної стратегії;
- контроль ризику та аварійну зупинку;
- dashboard реальних позицій і P&L;
- історію угод;
- сповіщення;
- підтримку користувача.

Остаточний склад тарифу затверджується після оцінки технічної собівартості,
підтримки, партнерських виплат і готовності SaaS-функцій.

## 6. Депозит

Попередній технічний мінімум: 10 USD.

Потрібно розділяти:

- **технічний мінімум** — найменша сума, з якою біржа та алгоритм здатні
  створити допустимий ордер;
- **рекомендований мінімум** — сума, на якій стратегія має економічний сенс
  після комісій, funding, прослизання і ціни підписки;
- **мінімум платного клієнта** — сума, за якої підписка 100 USD не робить
  використання продукту очевидно збитковим за економікою.

Депозит 10 USD наразі вважається лише технічною гіпотезою для перевірки, а не
готовою маркетинговою пропозицією. Необхідно розрахувати рекомендований депозит
для тарифу 100 USD на місяць.

## 8. Технічна розбіжність із поточним репозиторієм

Поточна документація репозиторію описує міжбіржову двоногу систему, яка для
реального виконання потребує щонайменше двох біржових підключень. Первинне
продуктове рішення передбачає Binance-only і торгівлю через spot/futures.

До затвердження MVP Андрій має визначити одне з двох:

1. SaaS запускається на іншому алгоритмі, який працює всередині Binance через
   spot/futures; або
2. перша версія залишається міжбіржовою і вимагає дві чи більше біржі.

Це рішення впливає на onboarding, мінімальний депозит, маркетинговий офер,
ризики, строки розробки й підтримку.

## 9. Робоче позиціонування

Попередня версія:

> CryptoBOT — це SaaS-платформа для автоматизованої торгівлі через API
> особистого біржового акаунта: користувач безкоштовно перевіряє алгоритм у
> Paper, після чого може підключити Binance та запустити реальну торгівлю з
> визначеними лімітами ризику.

Фінальне позиціонування затверджується після підтвердження торгової стратегії,
мінімального депозиту та готовності Binance-only.
